# V7RC APP × Microduck 整合計畫

日期：2026-11-06。狀態：初步設計提案，未實作或驗收。

## 使用者確認的研究順序

1. 在本機搭建 Microduck 模擬器。
2. V7RC APP 串接並成功控制模擬器中的 Microduck。
3. 使用模擬環境及訓練工具訓練策略；使用者日後可提供 RTX 5090 伺服器。
4. 新策略仍可透過 V7RC 控制；實機效果另行驗收。

參考 [可行性評估與查閱版本](feasibility-2026-11-06.md)。優先評估 Wi-Fi UDP 橋接；本機完成既有策略控制後再進入 GPU 訓練。

第一階段進度：[Mac 模擬器已搭建並完成指定操作點的基本動作驗證](../validation/2026-11-06-macos-simulator.md)。低速穩定性與速度／直線精度仍有限制，需在第二階段明確保留。

第二階段進度：[SRT 四通道 UDP 橋接已開發](v7rc-wifi-udp.md)，本機 sender 的端到端測試通過；使用者已確認手機 APP 試連，頭部映射依回饋交換並反相，詳細動作驗收仍需逐項記錄。

## 目標與候選架構

以 V7RC APP 搖桿及按鍵控制 Microduck 的移動與動作。建議先研究以下流程：

```text
V7RC APP → 相容的通訊接收端 → V7RC 封包解析／輸入映射
         → Microduck 控制介面 → 既有機器人控制迴圈
```

提案由橋接程式將搖桿數值轉成移動意圖，透過既有機器人控制介面送出。理由是上游已有控制迴圈與策略執行機制，整合端應先確認如何正確使用它。參考：[Microduck 架構來源](../microduck/overview.md)、[V7RC 協定來源](../v7rc/protocol-notes.md)。

## 通訊路徑評估

| 候選方式 | 適用條件 | 必須先驗證 |
| --- | --- | --- |
| Microduck 上實作 V7RC BLE 接收 | 系統可提供 APP 所需 GATT | 與既有 Bluetooth 服務的資源／生命週期衝突 |
| 外接 BLE 接收板，再橋接到 Microduck | 接收板相容 V7RC，且可連到機器人 | 板型、轉送介面、延遲、失聯處理 |
| 網路橋接 | 實際 V7RC 版本確實支援所需網路通訊 | 傳輸模式、封包規格與本機網路條件 |

目前尚未選定方式，不假設 Microduck 原生 BLE 與 V7RC 直接相容。

## 分階段工作

1. **版本與介面盤點**：取得需要的倉庫並固定 commit；確認 APP 版本、硬體與控制入口。
2. **封包觀察**：以接收端記錄搖桿、按鍵、中立與斷線封包，完成通訊規格。
3. **離線橋接**：驗證封包解析、軸向、死區、限幅、按鍵去重及輸入逾時，不送實機。
4. **模擬器驗證**：核對控制映射、回中、切換控制權及失聯行為，記錄延遲。
5. **實機整合**：確認機器人狀態與操作條件後逐步測試，保留獨立實機紀錄。

## 首版需定義的控制契約

- 每個通道對應的前進、側移、轉向或其他功能，以及方向、單位、範圍與死區。
- 按鍵觸發動作的先決狀態與成功／失敗回報。
- 搖桿回中、封包逾時、APP 斷線、橋接重啟時的處理。
- 速度歸零、停止策略、坐下、卸力等行為分別定義，不將其視為同一種「停止」。
- 上游手把、APP 與橋接程式之間的控制權仲裁。

上述契約均待原始碼與實測確認，目前不指定 API 名稱、UUID 或控制頻率。
