# 2026-11-06：CAMERA OFF 的網路排查

環境：第一輪 iPhone iOS V7RC 3.00.006 提供個人熱點，Mac=172.20.10.2/28、手機=172.20.10.1。暫停後使用者切到一般 Wi-Fi；恢復檢查時舊程序已結束，重新啟動相同程式並帶到前台。第二輪 Mac=192.168.52.77/24、相機與控制來源=192.168.52.163。

## 已確認

- `socketfilterfw --getglobalstate` 回覆 `Firewall is disabled. (State = 0)`；block-all 關閉、stealth 關閉。沒有修改防火牆設定。
- `lsof` 顯示同一個 mjpython 程序綁定 IPv4 `*:8800/UDP`、`*:1234/UDP`；控制橋接綁定 `*:6188/UDP`。不是相機程序沒啟動或只監聽 localhost。
- `route -n get 172.20.10.1` 確認到手機的路由走 en0，MTU 1500。Mac 有 ppp0 預設路由，但手機目的位址有 en0 的本地路由，不能僅因 VPN 存在就判定回程被 VPN 導走。
- 控制接收紀錄確實持續收到手機 172.20.10.1 的有效 SRT，約 33 FPS；熱點並非全面阻擋手機到 Mac 的 UDP。
- 相機接收器會記錄所有到達 socket 的 datagram，包括不符合協定的資料。第一次相機測試僅有本機來源；之後控制改送 8800，已收到手機的 SRT／LE 控制封包，invalid 增至 685。這些不是相機 EF00／EF02，故 OFF 符合協定。
- 本地 iOS `Camera757UDPClient.swift` 啟動時強制以 `IP_BOUND_IF` 綁定 en0；`tick()` 自動送 EF00。`TenserFlow/IpCamera.swift` 呼叫 SDK，但沒有掛上 `onStatus` 顯示 socket 啟動錯誤。因此相機選項已儲存／start 回傳 true，不代表 socket 或路由成功。

## 對照測試與目前判讀

| 測試 | 結果 |
| --- | --- |
| 個人熱點、控制→6188 | 手機 SRT 可達，約 33 FPS |
| 個人熱點、控制暫改→8800 | 手機來源 172.20.10.1，20 bytes SRT／LE 控制資料確實可達；使用者確認測後改回 6188 |
| 個人熱點、相機→8800 | 未觀察到手機 EF00／EF02，CAMERA OFF |
| 一般 Wi-Fi、相機→8800 | 收到 192.168.52.163:50812 的有效訂閱與回饋；3 次 probe、300 次 feedback；已送 91 張影格、1267 分片 |
| 一般 Wi-Fi、控制→6188 | 同一裝置取得新來源鎖定，約 35 FPS，armed=true |
| 模擬器健康 | 重啟後 healthy、50/50 Hz、0 missed |

已確認 CAMERA OFF 與「iPhone 作個人熱點時，相機路徑沒有把有效訂閱送到 Mac」相關；換成一般 Wi-Fi 後相同發送程式可立即 ON。可排除 Mac 全面封鎖 UDP 8800、相機未監聽及此格式完全不相容。未調整防火牆、PF 或傳輸格式。

本地 iOS SDK 強制綁定 en0 是最直接的疑點；原始碼三個相關檔案 SHA256 與第一輪相同。**尚未讀取手機的實際路由或 sendto errno，因此不能把 en0 綁定認定為唯一已證明的根因**；使用者隨後確認一般 Wi-Fi 下「看得到，影像正常」，手機顯示驗收通過。

目前操作方案：兩端連同一 Wi-Fi，控制 IP=192.168.52.77、Port=6188；相機同 IP、Port=8800。關閉相機超過 3 秒後 OFF 為正常逾時，並非服務故障。

若要支援 iPhone 本身提供熱點，下一步應在 APP 相機路徑記錄 socket 建立／IP_BOUND_IF／sendto 的 errno 與目的端點，將固定 en0 改為可驗證的路由選擇或失敗後回退；不能只在 Mac 對任意控制封包回傳影像，因相機使用獨立接收 socket／Port。本次尚未修改 APP。

證據：[熱點下控制送 8800](evidence/2026-11-06-network/hotspot-control-to-8800.jsonl)、[一般 Wi-Fi 相機](evidence/2026-11-06-network/router-v7rc-video.json)、[一般 Wi-Fi 控制](evidence/2026-11-06-network/router-v7rc-input.json)。

## 抓包限制

嘗試唯讀 tcpdump（僅限手機 IP 與 6188／8800）遭 BPF 裝置權限拒絕；PF 狀態亦需管理員權限。`sudo -n` 確認沒有現成免密權限，未索取密碼、未提升永久權限或改動安全設定。因此目前的「未收到」指應用 socket 觀察，不能宣稱已證明封包未到網卡。

證據存於 [網路證據目錄](evidence/2026-11-06-network/)。相機封包格式與解碼測試見 [影像驗證](2026-11-06-v7rc-video.md)。來源版本同該文件；本次未修改 APP、模擬器或相機協定。

後續持續觀察：手機在一般 Wi-Fi 重新開啟相機後再次有效訂閱並送 EF02，累計超過 350 張。最新機器快照見 [router-live-video.json](evidence/2026-11-06-network/router-live-video.json)。此回合沒有本機測試相機接收端參與；使用者已回覆「看得到，影像正常」，確認手機顯示通過。
