環境與上游 commit 同 [操作與協定文件](../integration/v7rc-video-feasibility.md)。MacBook Pro M4 Pro、MuJoCo 3.10.0、Python 3.12.16。本次新增 `bridge/camera757.py`、`bridge/microduck_camera.py`，擴充 `bridge/microduck_hud.py`。上游仍僅使用既有 body-module 兩行補丁，microduck_rl 未修改。

目前沒有發現發送端封包格式不相容。此結論限於已檢查的本地 iOS 原始碼與實際輸出，不等於手機顯示驗收通過。Mac 8800 的所有接收資料都會記錄類型／長度／前 8 bytes；目前僅看到本機來源，尚未看到手機來源，亦非收到未知格式後被拒絕。

使用者確認 iPhone 開熱點給 Mac；本地 SDK 強制 en0，可能與熱點主機路由有關。待同一 Wi-Fi 路由器下重試，再檢查手機 PEER 與影像。未修改 APP、未刷 ESP32／Ameba，也未調整主機防火牆。

## 重現

執行 `microduck_rl/.venv/bin/python -m unittest discover -s tests -v`。本機收圖可在**手機相機關閉且沒有其他接收端**時執行 `microduck_rl/.venv/bin/python scripts/verify-v7rc-video.py`。此腳本會暫時成為相機 peer；結束 3 秒後過期，請勿把測試 ON 誤當手機成功。

既有 iOS 接收器互通測試：

```sh
IOS_SDK='../../20260511V7RC-APP/V7RC%20IOS%20Version/Vendor/V7RCToySDK/ios-v7rc-ble-toy-sdk/Sources/V7RCToySDK'
/usr/bin/swiftc -module-cache-path .tools/swift-cache \
  "$IOS_SDK/Camera757Codec.swift" "$IOS_SDK/Camera757JpegHeaders.swift" \
  tests/native/main.swift -o .runtime/camera757-check/ios-check
.runtime/camera757-check/ios-check .runtime/camera757-check/vector-latest.json
```

本機 SDK 檔案 SHA256 在 source-files.json；原始來源中的工作樹版本以該 hash 為準，不能只靠 Git HEAD 推定。

## 後續網路對照結果

同日暫停後恢復：一般 Wi-Fi 下 Mac=192.168.52.77、手機=192.168.52.163，收到相機 EF00／EF02，已送 91 張並確認原生 HUD CAMERA ON。熱點下 8800 可接收手機控制資料，故不是 Mac 全面封鎖此 Port。詳細證據與 en0 疑點的驗證界線見 [網路診斷](2026-11-06-udp8800-network.md)。先前「未收到手機相機封包」僅描述個人熱點那一輪。

## 手機顯示驗收通過

2026-11-06（Asia/Taipei），使用者於一般 Wi-Fi 下回覆「看得到，影像正常」。640×360 頭部相機影像從模擬器經 UDP 到 iOS V7RC 的完整顯示流程通過。此結論不包含個人熱點模式、延遲量測或實體 Microduck 相機。
