MICRODUCK × V7RC

操作指引

透過 V7RC APP，以 Wi-Fi UDP 控制 Microduck 模擬器，並回傳 640×360 頭部相機影像。包含 SRT 四通道橋接、接收 FPS、雙搖桿、連線 IP／Port 與相機送出影格 HUD。

macOS Apple Silicon 已完成本機與手機控制／影像驗收。Linux 提供原生安裝與啟動，隔離容器測試另列於驗證紀錄；實際桌面、GPU 與手機網路仍待目標機驗收。Windows 11 使用 WSL2 Ubuntu＋WSLg，提供 PowerShell 啟動器；不是原生 Windows robotd，Windows 目標機仍待驗收。

安裝指引

新環境先完成安裝指引。既有 Louis Mac 環境可執行 scripts/link-workspace 重用同層上游與工具；此命令不適用尚未安裝的全新機器。所有下列相對命令均從整合 Repo 根目錄執行。

圖形安裝包與桌面啟動

從 GitHub Release 下載目前版本的未簽署測試版。Mac 使用 macOS 13 以上的 universal DMG；Windows 使用 Windows 11 x64 EXE，內含 .NET 執行環境，模擬器仍在 WSL2 Ubuntu 執行。這是網路安裝程式，第一次需要網路與約 20 GB 可用空間，不是離線的完整模擬器。

Mac：開啟 DMG 裡的 Microduck V7RC App，選擇語言並按「檢查環境」。安裝計畫會列出缺少的 Apple 開發工具、Homebrew／CMake／pkg-config，以及固定版本的上游、Rust、Python 與依賴。按「安裝／修復」並確認後才開始下載，請跟著終端機完成系統對話框與密碼操作。程式只在所有步驟成功後寫入完成狀態，並複製 App 到使用者 Applications、建立桌面啟動圖示。

Windows：開啟 EXE，先檢查環境並確認安裝。若缺少 WSL／Ubuntu，會請求系統安裝；需要重新開機時請完成後重開安裝程式。先在 Ubuntu 完成一般 Linux 使用者初始化，再按安裝；Linux 系統套件安裝可能要求 sudo 密碼。成功後桌面圖示會啟動模擬器與橋接，不會自動關閉其他 WSL 發行版或修改防火牆。手機連線仍須依前述 mirrored networking 與窄範圍 UDP 規則設定。

桌面圖示會自動啟動已完成的安裝，並保留終端機顯示下載、編譯與執行訊息。初次安裝會先編譯 runtime 並取得策略；之後可由同一圖示啟動。若研究版或其他程式占用 6188／8800／1234，會停止並提示，不會自動停止別的專案。停止可使用視窗中的「停止模擬器」或關閉啟動終端機。

目前是未簽署／未公證測試版，系統可能顯示發行者或信任提示；正式部署應使用組織簽章。Mac 預設資料位於 ~/Library/Application Support/MicroduckV7RC；Windows 啟動器位於 %LocalAppData%/Programs/MicroduckV7RC，模擬資料位於 Ubuntu 的 ~/.local/share/microduck-v7rc。版本目錄彼此分開，既有研究 Repo 不會被搬移或覆寫。

前置條件

建議 Ubuntu 24.04 桌面／WSL2 Ubuntu-24.04；Linux x86_64 或 aarch64。需 Git、curl、C/C++ 工具鏈、CMake、pkg-config、OpenSSL／udev／ALSA 開發套件與 OpenGL／EGL。桌面需要可用的圖形驅動與 DISPLAY／Wayland；無視窗運算仍須依相機需求配置 EGL。這是單機模擬與推論安裝，不是 GPU 訓練環境。

Windows 11／WSL2 安裝

建議 Windows 11 22H2 以上，啟用虛擬化，使用最新 WSL2 與 GPU 驅動。先在管理員 PowerShell 安裝 Ubuntu-24.04，依提示重新啟動，再於 Ubuntu 終端機依 Linux 步驟安裝。Repo 放在 Linux 家目錄，不要共用 Windows 的 Python .venv 或從 /mnt/c 執行。WSLg 提供模擬器視窗。

wsl --install -d Ubuntu-24.04
wsl --update

Windows 手機 UDP 網路

手機需要能主動連進 WSL。使用 mirrored networking，並在既有 %UserProfile%\.wslconfig 的 [wsl2] 區段加入設定，保留其他設定。先儲存所有 WSL 工作再執行 wsl --shutdown（會停止所有發行版），然後重開 Ubuntu。若仍被擋，只新增 UDP 6188／8800 的必要規則；不要關閉整個防火牆。

[wsl2]
networkingMode=mirrored

Windows 手機 UDP 網路 / PowerShell

手機需要能主動連進 WSL。使用 mirrored networking，並在既有 %UserProfile%\.wslconfig 的 [wsl2] 區段加入設定，保留其他設定。先儲存所有 WSL 工作再執行 wsl --shutdown（會停止所有發行版），然後重開 Ubuntu。若仍被擋，只新增 UDP 6188／8800 的必要規則；不要關閉整個防火牆。

wsl --shutdown

Windows 手機 UDP 網路 / Firewall

Windows 防火牆命令需在管理員 PowerShell 手動執行，僅於尚未有等效規則且目前網路為可信任的 Private profile 時使用。Hyper-V 的 WSL 規則另列；命令不存在時先更新 Windows／WSL。Linux 則依實際啟用的防火牆放行手機到 6188／8800。

New-NetFirewallRule -DisplayName "Microduck V7RC UDP" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 6188,8800 -Profile Private -RemoteAddress LocalSubnet
New-NetFirewallHyperVRule -Name "MicroduckV7RC" -DisplayName "Microduck V7RC WSL" -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol UDP -LocalPorts 6188,8800 -Action Allow

可選的 PowerShell 啟動器

可從 Windows 可讀到的本 Repo windows/ 目錄執行；LinuxRepo 是 WSL 內的絕對路徑。預設路徑為 Linux 家目錄下的 microduck-v7rc。若多張網卡或 VPN，明確指定手機可達的 Windows LAN IPv4。主要使用方式仍可直接在 Ubuntu 終端機執行兩個 Shell 啟動命令。

.\microduck-v7rc.ps1 -Action Serve -Distribution Ubuntu-24.04 -LinuxRepo /home/louis/microduck-v7rc -AdvertiseIP 192.168.1.20
.\microduck-v7rc.ps1 -Action Bridge -Distribution Ubuntu-24.04 -LinuxRepo /home/louis/microduck-v7rc -AdvertiseIP 192.168.1.20

安裝後檢查

doctor 顯示平台、對外 IP、IPC socket 與圖形環境。多網卡、VPN 或 WSL 顯示錯誤 IP 時，指定 MICRODUCK_ADVERTISE_IP；這只調整顯示給 APP 的 IP，不會修改路由或防火牆。更換 IP 後，APP 控制與相機都要更新；換手機來源 IP 後重啟橋接。

microduck_rl/.venv/bin/python -m unittest discover -s tests -v

啟動與連線 — 1

開啟模擬器後應站起，主控台顯示 healthy。控制橋接收到有效回中封包後，左上變 LIVE，搖桿反映原始輸入。開啟 APP 相機後 CAMERA ON、PEER 為手機 IP，TX FRAMES 增加。

scripts/microduck-sim serve

啟動與連線 — 2

保留模擬器終端機，另開第二個終端機啟動橋接。手機與電腦使用同一台 Wi-Fi 路由器；APP 的控制與相機 IP 都填模擬器右上顯示的 IPv4。

scripts/v7rc-bridge

APP 設定與通道

IP 使用目前的 LAN IPv4，不使用固定範例 IP。控制：Wi-Fi UDP／SRT／6188；相機：UDP／8800。1234 是電腦的影像送出來源 Port，不是 APP 設定的目的 Port。 CH1 左右轉向；CH2 前後；CH3 頭部上下（反相）；CH4 頭部左右。範圍 1000–2000，中立 1500。啟動、失聯或重連後，四通道先回中才會重新啟用控制。

停止與無視窗模式

橋接終端機 Ctrl-C 會要求中立輸出；模擬器使用 down 或 serve 終端機 Ctrl-C。無視窗且不需要相機時停用 VIDEO；若需要無視窗相機，需自行驗證 EGL／GPU，不能把以下無相機模式當作視訊測試。

scripts/microduck-sim down
DUCK_SIM_VIEWER=0 MICRODUCK_VIDEO=0 scripts/microduck-sim serve

排查

  • WAITING／INPUT EXPIRED：確認控制目的 IP、UDP 6188、SRT 四通道，四軸回中；若更換手機或 Wi-Fi，重啟橋接清除來源鎖定。
  • CAMERA OFF：確認相機來源 UDP、目的 IP 與 8800，按下影像開啟；查看 .runtime/v7rc-video.json。沒有手機 datagram 表示尚未到接收器；不要把 127.0.0.1 本機測試當成手機連線。
  • CAMERA ON 但沒圖：檢查 PEER、TX FRAMES、回程 UDP 與 APP 格式；ON 不能單獨代表成功。先使用一般 Wi-Fi，避免 iPhone 自身提供個人熱點。
  • WSL 收不到：確認 mirrored、Private／Hyper-V 防火牆與手機／電腦同一 LAN；傳統 netsh portproxy 只處理 TCP，不能用來修復此 UDP 串流。
  • 沒有視窗：Linux 確認 DISPLAY／Wayland 及 OpenGL，Windows 確認 WSLg 與驅動；Mac 由腳本選 mjpython。
  • Port 已使用：先查占用程序，只停止本 Repo 的舊實例；不要全域 pkill 或停止其他專案。

驗收清單

在目標電腦依序確認：站立／健康 → 四通道回中 → 前後與轉向 → 頭部上下／左右 → 影像與方向 → 關閉再開 → 停止封包後中立保護。記錄 OS、架構、GPU、IP、上游 commit 與實測結果。Linux 容器測試不能替代桌面或手機驗收；Windows 啟動器語法檢查也不能替代真實 WSL 測試。

已知限制

個人熱點模式曾收不到 iOS 相機訂閱；同一 Wi-Fi 下已驗收正常。低速步行、速度追蹤及直線精度有上游限制，不能以收到 UDP 推定動作精度。CAMERA ON 與 TX FRAMES 代表訂閱有效／主機送出，仍須實際確認 APP 顯示。模型授權請閱讀上游 LICENSE-MODELS.md（含 CC BY-NC-SA 4.0）。

APP 设置与通道

IP 使用当前 LAN IPv4，不使用固定示例 IP。控制：Wi-Fi UDP／SRT／6188；相机：UDP／8800。1234 是电脑发送图像的源 Port，不是 APP 设置的目标 Port。 CH1 左右转向；CH2 前后；CH3 头部上下（反相）；CH4 头部左右。范围 1000–2000，中立 1500。启动、失联或重连后，四通道先回中才能重新启用控制。

故障排查

  • WAITING／INPUT EXPIRED：确认控制目标 IP、UDP 6188、SRT 四通道，四轴回中；更换手机或 Wi-Fi 后重启桥接清除来源锁定。
  • CAMERA OFF：确认相机来源 UDP、目标 IP 和 8800，并开启图像；查看 .runtime/v7rc-video.json。没有手机 datagram 表示尚未到接收器；不要把 127.0.0.1 本机测试当作手机连接。
  • CAMERA ON 但无图：检查 PEER、TX FRAMES、回程 UDP 与 APP 格式；ON 不能单独代表成功。先使用普通 Wi-Fi，避免 iPhone 自身提供个人热点。
  • WSL 收不到：确认 mirrored、Private／Hyper-V 防火墙和手机／电脑同一 LAN；传统 netsh portproxy 仅处理 TCP，不能用于修复 UDP 串流。
  • 没有窗口：Linux 检查 DISPLAY／Wayland 与 OpenGL，Windows 检查 WSLg 和驱动；Mac 由脚本选择 mjpython。
  • Port 被占用：先查询占用进程，仅停止本 Repo 的旧实例；不要全局 pkill 或停止其他项目。

验收清单

在目标电脑依次确认：站立／健康 → 四通道回中 → 前后和转向 → 头部上下／左右 → 图像与方向 → 关闭后重开 → 停止封包后的中立保护。记录 OS、架构、GPU、IP、上游 commit 和实测结果。Linux 容器测试不替代桌面或手机验收，Windows 启动器语法检查也不替代真实 WSL 测试。

已知限制

个人热点模式曾无法收到 iOS 相机订阅；同一 Wi-Fi 下已验收正常。低速步行、速度跟踪和直线精度有上游限制，不能以收到 UDP 推断动作精度。CAMERA ON 和 TX FRAMES 表示订阅有效／主机发送，仍须实际确认 APP 显示。模型许可证请阅读上游 LICENSE-MODELS.md（含 CC BY-NC-SA 4.0）。

MICRODUCK × V7RC

How to use

Control the Microduck simulator with the V7RC app over Wi-Fi UDP and stream its 640×360 head camera. Includes a four-channel SRT bridge and an overlay showing input FPS, two joysticks, connection addresses, and camera frame counts.

macOS Apple Silicon has passed local simulation and phone control/video acceptance. Native Linux setup and launch paths are implemented; isolated container results are reported separately. Desktop graphics, GPU drivers and phone networking still require target-host acceptance. Windows 11 runs the Unix robot stack in WSL2 Ubuntu with WSLg and a PowerShell frontend. This is not native Windows robotd support; real Windows acceptance is pending.

Download and install

Current version: 0.1.0-preview.8 · GitHub Release

  • macOS 13+ · Apple Silicon / Intel: MicroduckV7RC-0.1.0-preview.8-macOS-universal.dmg · SHA256
  • Windows 11 x64 · WSL2 Ubuntu: MicroduckV7RC-0.1.0-preview.8-Windows-x64.exe · SHA256

Open the downloaded installer, check prerequisites and confirm installation. Launch from the desktop icon after setup completes. This repository is public; Release installers can be downloaded without signing in to GitHub.

Mac installation, desktop launch, and V7RC control and video were verified on preview.2. The preview.3 drive calibration completed 54 simulator trials on Mac. Full WSL2 installation and phone operation still need validation on a Windows machine.

Installation guide

Complete the installation guide on a new machine. The existing Louis Mac workspace can reuse sibling checkouts and tools with scripts/link-workspace; that command does not install a fresh machine. Run all relative commands below from the integration repository root.

Graphical installers and desktop launcher

Download the current unsigned preview from GitHub Releases. Use the universal DMG on macOS 13+, or the self-contained EXE on Windows 11 x64. Windows includes its .NET runtime; the simulator runs inside WSL2 Ubuntu. This is an online installer: initial downloads need internet and roughly 20 GB of free space, not a complete offline simulator bundle.

Mac: open Microduck V7RC inside the DMG, select a language and check the environment. The plan lists missing Apple developer tools, Homebrew/CMake/pkg-config, pinned upstreams, Rust, Python and dependencies. Installation starts only after confirming Install / repair. Complete system dialogs and password requests in the terminal. Only successful completion writes a ready receipt, copies the app to the user Applications directory and creates the desktop icon.

Windows: open the EXE, inspect the environment and confirm installation. Missing WSL/Ubuntu triggers system installation; if Windows requests a reboot, complete it and reopen the installer. Initialize a normal Linux user in Ubuntu first, then install the simulator; Linux packages may require your sudo password. The desktop icon starts the simulator and bridge after success. The installer does not shut down unrelated WSL distributions or change firewall rules. Configure mirrored networking and the specific UDP rules described above for phone access.

The desktop icon automatically launches a completed installation and leaves a terminal showing download/build/runtime output. Initial setup prebuilds the runtime and downloads policies. Ports 6188/8800/1234 are checked before launch: another application using them causes a clear stop, never automatic termination of another project. Use Stop simulator or close the session terminal to stop.

This preview has no publisher signature/notarization, so the OS may display trust prompts. Use organizational signing for production deployment. Mac data defaults to ~/Library/Application Support/MicroduckV7RC; the Windows frontend lives in %LocalAppData%/Programs/MicroduckV7RC and simulator data in Ubuntu ~/.local/share/microduck-v7rc. Installations use separate version directories and do not move or overwrite the research workspace.

App settings and channels

Use the current LAN IPv4 address, not a fixed example address. Control: Wi-Fi UDP / SRT / 6188. Camera: UDP / 8800. Port 1234 is the computer’s outgoing video source port, not the camera destination configured in the app. CH1 steering; CH2 forward/reverse; CH3 head pitch (inverted); CH4 head yaw. Range 1000–2000, neutral 1500. All four channels must return to neutral after startup, timeout or reconnection before control is armed again.

Stop and headless mode

Ctrl-C in the bridge requests neutral output. Stop the simulator with down or Ctrl-C in its serve terminal. Disable VIDEO for headless use without a camera. A headless camera needs separately validated EGL/GPU support; the no-camera command below is not a video test.

scripts/microduck-sim down
DUCK_SIM_VIEWER=0 MICRODUCK_VIDEO=0 scripts/microduck-sim serve

Troubleshooting

  • WAITING / INPUT EXPIRED: check the control IP, UDP 6188 and SRT four-channel mode. Center all channels. Restart the bridge after changing phones or networks to clear the source lock.
  • CAMERA OFF: select UDP camera, check its IP and port 8800, and open video. Inspect .runtime/v7rc-video.json. No phone datagram means none reached the receiver. A 127.0.0.1 test subscription is not a phone connection.
  • CAMERA ON without a picture: inspect PEER, TX FRAMES, return UDP traffic and app compatibility. ON alone is not acceptance. Use a shared Wi-Fi router rather than having the receiving iPhone provide Personal Hotspot.
  • WSL receives nothing: check mirrored networking, Private/Hyper-V firewall rules and that both devices share the LAN. Traditional netsh portproxy handles TCP only and cannot forward this UDP stream.
  • No window: check DISPLAY/Wayland and OpenGL on Linux, WSLg and drivers on Windows. The Mac launcher selects mjpython automatically.
  • Port in use: identify its owner and stop only this repository’s old instance. Do not use global pkill or stop unrelated projects.

Acceptance checklist

On the target computer check, in order: standing/health, four-channel neutral, forward/reverse and turns, head pitch/yaw, picture/orientation, close/reopen, and neutral protection after input stops. Record OS, architecture, GPU, IP, upstream commits and observed results. Linux container checks do not replace desktop/phone acceptance; PowerShell parsing does not replace a real WSL run.

Known limitations

iOS camera subscriptions failed when the same iPhone provided Personal Hotspot; video passed on a shared Wi-Fi router. Low-speed walking, velocity tracking and straight-line accuracy have upstream limitations. Receiving UDP does not establish motion accuracy. CAMERA ON and TX FRAMES indicate an active subscription and host transmission; confirm the app display separately. Read upstream LICENSE-MODELS.md for model licensing, including CC BY-NC-SA 4.0.

New-NetFirewallHyperVRule -Name "MicroduckV7RC" -DisplayName "Microduck V7RC WSL" -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -Protocol UDP -LocalPorts 6188,8800 -Action Allow

起動と接続 — 2

シミュレーターの端末を開いたまま、別の端末でブリッジを起動します。スマートフォンと PC を同じ Wi-Fi ルーターに接続し、アプリの操作とカメラの両方にシミュレーター右上の IPv4 を設定します。

scripts/v7rc-bridge

アプリ設定とチャンネル

固定のサンプル IP ではなく現在の LAN IPv4 を使用します。操作は Wi-Fi UDP／SRT／6188、カメラは UDP／8800 です。1234 は PC の映像送信元 Port で、アプリに設定する宛先 Port ではありません。 CH1 は旋回、CH2 は前後、CH3 は頭部上下（反転）、CH4 は頭部左右です。範囲 1000–2000、中立 1500。起動、通信断、再接続後は全 4 チャンネルを中立に戻すまで操作を再開しません。

停止とヘッドレス実行

ブリッジ端末の Ctrl-C は中立出力を要求します。シミュレーターは down または serve 端末の Ctrl-C で停止します。カメラ不要のヘッドレス実行では VIDEO を無効にします。ヘッドレス映像には EGL／GPU の個別確認が必要で、以下のカメラなしコマンドは映像試験ではありません。

scripts/microduck-sim down
DUCK_SIM_VIEWER=0 MICRODUCK_VIDEO=0 scripts/microduck-sim serve

トラブルシューティング

  • WAITING／INPUT EXPIRED：宛先 IP、UDP 6188、SRT 4 チャンネルと全軸中立を確認します。端末やネットワーク変更時はブリッジを再起動して送信元ロックを解除します。
  • CAMERA OFF：カメラを UDP にし、宛先 IP と 8800 を確認して映像を開きます。.runtime/v7rc-video.json を確認し、スマートフォンの datagram がなければ受信側まで届いていません。127.0.0.1 の試験購読はスマートフォン接続ではありません。
  • CAMERA ON で映像なし：PEER、TX FRAMES、戻りの UDP、アプリ形式を確認します。ON だけで合格とは判定しません。受信 iPhone のインターネット共有ではなく共通 Wi-Fi を使用してください。
  • WSL に届かない：mirrored、Private／Hyper-V 規則、同じ LAN を確認します。従来の netsh portproxy は TCP 専用で、この UDP ストリームを転送できません。
  • ウィンドウがない：Linux は DISPLAY／Wayland と OpenGL、Windows は WSLg とドライバーを確認します。Mac はスクリプトが mjpython を選択します。
  • Port 使用中：使用プロセスを調べ、本 Repo の古いインスタンスだけを停止します。全体への pkill や他プロジェクトの停止は行わないでください。

受け入れ確認

対象 PC で、起立／health → 全軸中立 → 前後・旋回 → 頭部上下・左右 → 映像と向き → 閉じて再開 → 入力停止後の中立保護を順に確認します。OS、アーキテクチャ、GPU、IP、上流 commit と結果を記録してください。Linux コンテナー試験は GUI／スマートフォン確認の代用ではなく、PowerShell 構文確認も実際の WSL 試験の代用ではありません。

既知の制限

受信側 iPhone 自身がインターネット共有を提供する構成ではカメラ購読が届かず、共通 Wi-Fi では映像表示を確認済みです。低速歩行、速度追従、直進精度には上流の制限があります。UDP 受信だけで動作精度は保証できません。CAMERA ON と TX FRAMES は購読と PC の送信を示し、アプリ表示は別途確認します。モデルのライセンスは上流 LICENSE-MODELS.md（CC BY-NC-SA 4.0 を含む）を確認してください。
